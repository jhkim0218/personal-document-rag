# Personal Work Document RAG

파일명만 찾는 로컬 검색을 넘어, PDF·DOCX·Markdown·TXT의 **내용을 검색하고 근거 문단을 인용하는 개인 업무 문서 RAG**입니다. 한 명의 사용자가 허용된 문서 폴더를 회사 PC에서 빠르게 탐색·검증하는 용도입니다.

이 프로젝트는 “챗봇을 만들었다”보다 검색·인용·답변 보류의 품질을 같은 평가 세트에서 측정하고 개선하는 데 초점을 둡니다.

## 실행

**개인 업무 효율 기록** 화면에서 대표 과제 10~15개를 입력하면 기존 탐색과 RAG를 비교하는 순서를 배정합니다. **다음 측정 시작**을 누르고 해당 방식으로 탐색한 뒤, 원문을 확인한 시점에 판정과 함께 종료하세요. 과제 해결·원문 확인·수정 불필요·실패 없음이 모두 충족돼야 ‘검증 성공’으로 표시됩니다. 이는 사용자의 자기 판정이지 독립 검수 결과가 아닙니다. 기록은 DB 옆 `*.study.sqlite3`에 비공개 저장되며 Git에서 제외됩니다. 앱이 꺼져 중단된 기록은 시간·성공 없이 남고, 남은 측정을 취소한 뒤 **중단 측정 다시 배정**으로 새 측정을 만들 수 있습니다. 화면의 **익명 집계 내려받기**는 과제명·메모·경로·개별 기록을 제외하고 방법별 성공률·중앙 시간·쌍별 시간차만 JSON으로 저장합니다. 과제·메모나 원본 문서를 그대로 경력서·공개 저장소에 복사하지 마세요.

자동 갱신은 화면의 **자동 갱신 시작/중지** 또는 `python app.py --mode offline --watch`로 사용합니다. 활성 소스와 제외 규칙을 그대로 따르며, 5초 간격으로 파일 해시를 비교하고 최소 2초 이상 같은 상태로 관찰된 뒤 변경 색인을 시작합니다. 실제 기본 간격에서는 대체로 두 번의 폴링이 필요합니다. API 모드에서는 자동 색인도 전송·비용을 발생시킵니다. 실패는 30초 뒤 다시 시도합니다. 자동 갱신 중지는 현재 색인을 취소하지 않으며 **색인 중지**로 자동 작업을 취소하면 감시도 일시 중지됩니다. 재시작 후 자동 갱신은 다시 켜야 합니다.

API 임베딩은 한 요청에 최대 64개 입력·64,000 UTF-8 바이트로 나누어 전송합니다. 개별 입력은 8,000바이트 이하로 제한합니다. 한도를 넘는 청크나 질문은 자동으로 자르지 않으므로 청크 크기 또는 질문 길이를 줄이세요. 일부 묶음이 실패하면 해당 문서의 이전 색인을 보존하며, 재시도 시 이미 성공한 묶음도 다시 계산할 수 있습니다.

API 모드는 일부 일시 오류에 최대 3회 재시도합니다. 인증/할당량 오류는 자동 재시도하지 않습니다. `/api/status`의 `api_attempts`는 현재 프로세스의 최근 100회이고, `api_usage`는 DB 옆 `*.usage.sqlite3`에 재시작 뒤에도 남는 최근 100회입니다. 두 기록 모두 모델·엔드포인트·시도·상태·지연·응답 토큰 수만 저장하며 원문·질문·응답 본문·API 키는 저장하지 않습니다. 응답이 없는 요청의 사용량/비용은 추정하지 않습니다. timeout 재시도에는 중복 계산·과금 가능성이 있습니다.

비용은 최신 [공식 모델 가격표](https://developers.openai.com/api/docs/models/compare)를 확인한 뒤 사용자가 기준일과 모델별 토큰 단가를 넣었을 때만 계산합니다. 앱은 단가를 자동 다운로드하거나 모델명을 추정하지 않습니다. 아래 JSON을 개인 경로에 두고 실행하세요. `input`만 있는 임베딩 모델은 output 항목을 생략할 수 있습니다. 단가가 없거나 API가 필요한 토큰 수를 주지 않으면 비용은 `null`로 남습니다.

```json
{
  "effective_date": "2026-09-06",
  "models": {
    "your-embedding-model": {"input_usd_per_million_tokens": 0.00},
    "your-generation-model": {"input_usd_per_million_tokens": 0.00, "output_usd_per_million_tokens": 0.00}
  }
}
```

```powershell
python app.py --pricing D:\private\rag-pricing.json
```

기록된 추정값은 해당 요청의 실제 응답 토큰과 JSON에 남긴 기준일/단가만 곱한 값입니다. 캐시·도구 호출·지역 처리 가산·세금·프로모션·timeout 후 중복 청구는 자동으로 추정하지 않으므로 비용 보고에는 별도로 명시하세요.

화면 요청은 최대 120초 동안 응답을 기다립니다. 시간 초과는 브라우저의 대기 중단이며 서버 색인 작업의 취소를 뜻하지 않습니다. 색인 요청이 늦어지면 **작업 상태 새로고침**으로 실제 상태를 확인하세요. 설정 저장도 서버에 반영됐을 수 있으므로 새로고침해 확인한 뒤 재시도합니다. 요청을 자동으로 다시 보내지는 않습니다.

브라우저 요청/버튼 복구 검증은 개발 환경의 Node.js 18 이상에서 `node tests/test_web_requests.cjs`로 실행합니다. 앱 실행 자체에는 Node.js가 필요하지 않습니다.

Python 3.11 이상에서 실행합니다.

```powershell
python -m pip install -r requirements.txt
python app.py --data data/sample
```

API 키가 있어도 외부 전송 없이 실행하려면 다음 명령을 사용합니다.

```powershell
python app.py --data data/sample --mode offline --open-browser
```

`offline`은 로컬 해시 검색과 원문 발췌만 사용합니다(학습된 로컬 LLM이 아닙니다). 기본 `auto`는 기존처럼 환경의 API 키를 사용하므로 외부 전송이 가능합니다. 화면 상단에 실행·검색·생성 모드와 전송 여부를 표시합니다. 모드는 실행 때마다 지정하며, DB에 저장된 이전 벡터와 모드가 다르면 변경 파일 색인으로 재색인해야 합니다. `--open-browser`는 기본 브라우저에 로컬 주소를 열고, 실패해도 서버를 유지하며 수동 접속 주소를 안내합니다. 브라우저 자체의 동기화·확장 프로그램 통신은 이 앱의 offline 옵션이 제어하지 않습니다.

브라우저에서 `http://127.0.0.1:8000`을 엽니다. 실제 문서를 사용할 때는 `--data D:\허용된\문서폴더`처럼 사용자가 처리 권한을 가진 로컬 폴더만 지정합니다. 원본 문서는 수정하지 않으며 SQLite 인덱스는 기본적으로 `.local/rag.sqlite3`에 저장됩니다.

OpenAI API 키가 있으면 아래처럼 설정해 근거 문단을 바탕으로 짧은 답변을 생성할 수 있습니다.

```powershell
$env:OPENAI_API_KEY = "..."
$env:RAG_MODEL = "gpt-5.2" # 선택 사항
python app.py --data D:\허용된\문서폴더
```

API 키가 있으면 색인 시 OpenAI embeddings를 사용하고, 답변 시 Responses API를 사용합니다. 키가 없을 때도 색인·검색·인용·답변 보류는 동작합니다. 이 경우에는 로컬 hash embedding과 추출형 근거 요약을 사용하므로 의미 검색과 종합 답변 품질은 API 기반 모드보다 낮을 수 있습니다. 키를 새로 설정하거나 embedding 모델을 바꾼 뒤에는 “변경 파일 색인”을 한 번 실행해 해당 모드로 다시 색인합니다.

이미 PC에 내려받은 sentence-transformers 임베딩 모델 또는 cross-encoder reranker가 있다면, `requirements-local.txt`를 설치한 뒤 아래처럼 **local** 모드로 실행할 수 있습니다. 모델 이름을 입력해 인터넷에서 받는 경로는 지원하지 않으며, 지정한 디렉터리가 없거나 런타임이 없으면 시작/색인 시 명확히 실패합니다.

```powershell
pip install -r requirements-local.txt
python app.py --mode local --local-embedding-model D:\models\embedding-model
# reranker만 쓰면 hash embedding + 로컬 cross-encoder를 사용합니다.
python app.py --mode local --local-reranker-model D:\models\reranker-model
python scripts/run_eval.py --data data/sample --questions data/eval/questions.jsonl --local-embedding-model D:\models\embedding-model --output results\local-model-evaluation.json
```

로컬 모델 평가는 모델 파일 수·바이트·SHA-256, Python 할당 peak, 지연시간과 검색 지표를 기록합니다. accelerator/native 메모리와 사람 검토 비용은 측정하지 않으며, 합성 개발 세트 점수는 실제 업무 품질이나 독립 holdout 성능이 아닙니다.

스캔된 PDF가 실제 검색 누락 원인일 때만 로컬 Tesseract를 설치하고 `--ocr`을 사용하세요. 텍스트가 이미 추출되는 PDF에는 실행하지 않으며, 이미지 전용 페이지는 `page N · OCR` 위치로 저장합니다. Tesseract 또는 지정 언어 팩이 없거나 OCR이 실패하면 해당 파일을 조용히 비워 색인하지 않고 오류·재시도 목록에 남깁니다.

```powershell
python app.py --mode offline --ocr --ocr-executable C:\Program Files\Tesseract-OCR\tesseract.exe --ocr-language kor+eng
```

구형 바이너리 `.hwp`는 자동 변환하지 않습니다. PC에 있는 HWP v5 호환 변환기(예: `hwp5txt`)를 명시하면 `HWP text`라는 파일 단위 위치로만 색인합니다. 암호화·매크로·이미지·세부 절 위치는 보존하지 않으므로, 정밀 인용이 필요하면 HWPX/PDF로 변환해 검토하세요. 변환기의 라이선스와 조직 사용 가능 여부도 별도로 확인해야 합니다.

```powershell
python app.py --mode offline --hwp-executable C:\tools\hwp5txt.exe
```

외부 API 요청은 최대 3회, 전체 45초 예산 안에서만 재시도하며 응답 본문은 2MB를 넘으면 거절합니다. 생성 답변이 12,000자를 넘으면 같은 근거의 추출형 답변으로 전환합니다. 사용 기록에는 모델·엔드포인트·시도·상태·지연·토큰 사용량과 선택한 가격 기준만 저장하며 문서/질문/응답 본문이나 키는 저장하지 않습니다.

입력 오류는 400, 동시에 실행할 수 없는 작업은 409, 예상하지 못한 서버 오류는 안전한 `server_error` JSON(500)으로 구분해 화면에 표시합니다. 내부 문서 내용이나 예외 세부 정보는 오류 응답으로 보내지 않습니다.

## 제공 기능

- PDF, DOCX, PPTX, XLSX, HWPX, Markdown, TXT와 선택형 HWP v5 변환에서 본문과 페이지·슬라이드·시트/셀·절·헤딩·문단 위치 추출
- SHA-256 기반 증분 색인: 바뀐 파일만 다시 처리하고 삭제 파일은 인덱스에서 제거
- vector-only, BM25, hybrid(RRF) 검색과 가벼운 재정렬 비교
- 색인 버전별 검색 캐시, 제목/경로 검색, 한국어 bigram 및 명시적 RRF/RTO 용어 대응
- 답변의 근거 파일·위치·발췌와 인용 번호 표시
- 근거가 없을 때 답변 보류
- 질문이 명시적으로 요구한 변경 전후·이유·p50/p95 중 일부가 원문에 없으면 `부분 근거`로 표시하고 생성 답변을 보류
- 단일 명시 변경 기록은 전·후·이유와 같은 원문 인용으로 표시하며, 파일 수정 시각만으로 최신 결정을 추정하지 않음
- 검색·질문 공통 근거 뷰어, 원본 파일 확인과 인용 복사 UI
- 현재 지정한 폴더로 검색·통계·출처 범위 제한, 파일별 트랜잭션으로 실패 시 기존 색인 보존
- 20개 합성 예시 문서와 50개 초안 평가 질의로 재현 가능한 오프라인 평가

## 검증

```powershell
python -m unittest discover -s tests -v
python scripts/run_eval.py --data data/sample --questions data/eval/questions.jsonl --output results/evaluation.json
python scripts/evaluate_grounding.py --output results/grounding_evaluation.json
python scripts/analyze_failures.py --output results/failure_analysis.json
python scripts/evaluate_answer_policy.py --output results/answer_policy_evaluation.json
python scripts/smoke_web.py
python scripts/benchmark_search.py
```

`results/evaluation.json`은 vector-only, BM25, hybrid, hybrid+reranking의 네 구성을 비교합니다. 정답 문서 Hit@5, 인용된 출처의 정답 파일 일치율, 인용 존재율, 답변 보류율, 검색/답변/전체 p50·p95 지연시간을 기록합니다. **인용의 의미적 정확도와 grounded answer rate는 아직 측정하지 않아 null입니다.** API 키가 환경에 있어도 평가에서는 외부 API를 사용하지 않습니다. 비용 `0.0`은 오프라인 API 비용만 의미하며 컴퓨팅·검토 비용은 포함하지 않습니다. 합성 질의의 라벨은 사람이 별도로 검증해야 하고, 답변 불가 질문도 3개뿐입니다. 코드·코퍼스·질의 해시와 실행 설정이 함께 저장됩니다.

`results/grounding_evaluation.json`은 가상 업무 fixture의 문서·헤딩·문장 gold 라벨을 사용해 상위 5개 검색의 **문자열 근거 recall**, 화면 발췌가 gold 문장을 실제 포함하는지, 인용이 붙은 답변 문장이 해당 원문에 그대로 있는지를 기록합니다. 같은 파일의 엉뚱한 문장과 유효 번호가 붙은 근거 없는 문장은 실패로 셉니다. 이 역시 문장 패러프레이즈/함의 판단이나 사람 검수 기반 의미적 인용 평가는 아니므로 `semantic_citation_precision`, `grounded_answer_rate`는 null로 유지합니다.

`results/relations_evaluation.json`은 상위 5개 검색과 **사용자가 직접 등록한** 프로젝트·결정·문서 지도의 gold 문서 coverage를 분리해 비교합니다. 현재 작은 AI 작성 fixture에서는 search 0.667, explicit relation 1.0이지만, 관계가 자동 추론되거나 실제 업무에서 같은 효과가 난다는 뜻은 아닙니다.

`results/failure_analysis.json`은 평가에서 재현된 검색/보류 실패 후보 5개를 질문·설정·상위 결과와 함께 뽑습니다. 원인, 수정, 전후 결과는 사람이 확인하기 전까지 `null`로 남기므로, 이 파일 자체를 개선 성과로 쓰면 안 됩니다.

`results/answer_policy_evaluation.json`은 명시적으로 불완전한 fixture에서 permissive와 `부분 근거` 정책을 비교합니다. 현재 required 2개 case에서는 permissive 0%, required-literal partial 100%이지만, 문서 범위를 case별로 고정한 정책 격리 실험이며 검색 품질·의미적 정확도·실사용 효과가 아닙니다.

처음 실행할 때 `--data`가 기본 폴더가 됩니다. 화면의 **검색 폴더 설정**에서 여러 폴더를 추가하고 활성/비활성, 포함/제외 하위 경로, 확장자를 설정할 수 있습니다. 저장 전 범위 미리보기로 대상 파일을 확인하세요. 설정을 저장하면 검색·문서 수·출처 범위에 즉시 반영되며 새 파일은 “변경 파일 색인” 후 검색됩니다. 설정은 DB 옆 `*.sources.json`에 저장되어 재시작 시 `--data`보다 우선합니다. 별도 설정을 사용하려면 다른 `--db`를 지정하세요.

`.git`, `.local`, 가상환경, 캐시, 임시 Office 파일은 기본 제외합니다. 하위 경로 필터는 glob이 아닌 상대 경로이며 `..`로 루트 밖을 지정할 수 없습니다. 비활성 폴더의 이전 색인은 DB에 남아도 검색/출처/원본 조회에 나오지 않습니다. PC 전체 자동 검색이나 폴더 자동 감시는 아직 없습니다. 변경 없는 파일도 해시 확인을 위해 읽지만 파싱·임베딩은 생략합니다.

색인은 백그라운드에서 실행됩니다. 진행 파일·완료 수·실패 원인·마지막 성공 작업 시각을 화면에서 확인하고, 실행 중에도 기존 문서를 검색할 수 있습니다. **실패 파일 재시도**는 실패한 파일만 처리하고 다른 문서를 삭제하지 않습니다. **전체 재색인**은 활성 범위의 모든 문서를 다시 처리하므로 API 모드에서는 비용이 발생할 수 있습니다. **색인 중지**는 파일 처리 경계에서 작동하며 이미 성공한 파일은 유지합니다. 진행 중인 파싱/API 호출을 강제 종료하지는 않습니다.

기본 **엄격 확인**은 수정 시각이 같아도 해시를 확인합니다. 체크를 해제하면 크기·수정 시각이 같은 파일을 건너뛰므로, 메타데이터를 보존한 내용 변경은 다음 엄격 색인까지 놓칠 수 있습니다. 파서/청킹 구현 변경 시 `pipeline_version`도 변경해야 이전 결과를 자동으로 재색인합니다. 작업 정보는 `*.jobs.json`, 파일별 최근 처리 상태는 로컬 SQLite에 저장되며 공개 Git에서 제외합니다. 저장 중 내용이 바뀐 파일은 기존 근거를 유지하고 재시도 대상으로 남깁니다.

근거 뷰어는 **색인 당시 청크 본문**을 보여줍니다. 원본 PDF는 페이지 링크로 확인하고, 다른 형식은 다운로드합니다. 원본이 변경되면 재색인 전까지 원본 열기를 거절해 오래된 인용과 새 파일이 섞이지 않게 합니다.

근거 뷰어의 **파일 시스템 수정 시각**은 색인된 파일의 메타데이터이며, 원문에 적힌 결정 날짜·적용일이 아닙니다. 둘이 다를 때 파일 시각만으로 최신 결정을 추정하지 마세요.

PPTX는 슬라이드 순서와 텍스트, XLSX는 시트명·셀 좌표·저장된 수식 결과, HWPX는 절 위치를 보존해 색인합니다. 선택형 HWP v5 변환은 파일 단위 `HWP text` 위치만 제공하며 암호화·매크로·차트·이미지 속 텍스트·수식 재계산·절 구조는 처리하지 않습니다.

질문 결과의 발췌는 청크 첫 문장이 아니라 질문과 어휘상 관련된 문장을 선택하며, **근거 위치 확인**을 누르면 해당 구간을 강조합니다. API에는 화면 발췌가 아닌 전체 청크를 전달합니다. 인용 번호와 문장별 인용 누락 검사는 의미적 정확도 검사가 아닙니다. 일부 날짜 질의는 날짜 패턴이 없으면 보류하며, 다른 유형의 근거 충분성·부분 답변·주장별 의미 검증은 아직 개선 중입니다.

**결정 이력 비교**는 같은 검색어의 상위 문서에서 `변경`, `changed`, `updated` 등의 명시적인 변경 문장만 모아 날짜순으로 보여 줍니다. 원문에 날짜·변경 전/후 값·이유가 없으면 해당 칸을 비워 두며, 결과가 없다는 사실을 ‘변경이 없었다’로 해석하지 않습니다. 이는 문서 간 동일 프로젝트/결정을 자동 판정하는 기능이 아니므로 각 원문 위치를 확인해야 합니다.

**관련 문서 묶음**은 같은 검색어의 상위 청크에서 문서별 최고 근거 한 개만 골라 보여 줍니다. 한 회의록의 여러 문단이 결과를 독점하는 일을 줄여 스펙·회의록·런북을 함께 확인하기 위한 화면이며, 검색에서 누락된 문서를 복원하거나 문서들의 관계를 자동 추정하지는 않습니다.

**프로젝트·결정·문서 관계**는 고급 로컬 설정에서 `프로젝트 → 결정 → 활성·색인된 문서 경로`를 직접 등록하는 작은 관계 지도입니다. 그래프 DB나 자동 온톨로지 추출은 사용하지 않습니다. 문서 폴더를 비활성화하거나 색인에서 사라지면 관계 설정은 보존되어도 탐색 결과에서는 숨겨집니다. 관계 이름과 경로는 로컬 `*.relations.json`에 저장되므로 공개 저장소에 넣지 마세요.

**답변·근거 검수 기록**에서 질문으로 만든 답변을 로컬 목록에 저장하고 원문 확인 뒤 `근거 충분`·`부분 근거`·`근거 부족/오답`으로 한 번 판정할 수 있습니다. 번호 인용이 있는 문장은 주장별로도 같은 세 판정 중 하나를 남길 수 있습니다. 두 후보 설정을 비교할 때는 저장 전에 각 답변에 실험 이름을 넣으면 로컬 화면에서 판정 수를 나란히 봅니다. 익명 집계 다운로드는 판정 건수만 포함하고 질문·답변·경로·발췌·메모·시각·실험 이름을 제외합니다. `*.reviews.sqlite3`에는 질문, 답변, 표시된 파일 경로·발췌, 검수 메모와 실험 이름이 저장됩니다. 모델에 보낸 전체 청크 context는 저장하지 않지만 회사 정보가 들어갈 수 있으므로 데이터베이스나 메모를 공개 저장소에 올리지 마세요. 이 기록은 사람이 입력한 판정이며 자동 의미 평가 결과가 아닙니다.

라벨 기준과 독립 검수 절차는 [사람 검수 프로토콜](docs/HUMAN_REVIEW_PROTOCOL.md)에 정리했습니다. 아직 실제 검수 표본이 없으면 이 프로토콜이나 빈 집계를 성과 수치로 쓰지 마세요.

## 실제 업무 효율 측정

대표 업무 과제 10~15개를 고르고, 기존 파일 탐색과 이 도구에서 시작부터 **원문을 열어 답을 확인할 때까지** 걸린 시간과 성공 여부를 비교하세요. 실제 문서·파일 경로·원문 발췌는 저장소와 데모에 넣지 말고, 집계 지표와 일반화한 실패 유형만 기록합니다.

## 제한 사항

- 로컬 fallback embedding은 비용 없는 기준선이지, 고품질 다국어 semantic embedding의 대체품이 아닙니다.
- 단일 개인 사용자·로컬 폴더 범위입니다. 조직 권한, 사내 커넥터, 자동 동기화는 의도적으로 포함하지 않았습니다.
- 인용 번호 형식 검증은 자동화되어도, 인용이 실제 주장을 뒷받침하는지의 의미적 평가는 표본을 사람이 검토해야 합니다.
- 한국어 bigram·소규모 용어 사전은 형태소 분석이나 학습된 의미 모델이 아닙니다. 개발 질의 11개는 튜닝에 사용했으며 독립 검증 자료가 아닙니다.
- 검색 캐시는 반복 계산을 줄이지만 벡터 전수 순회는 남아 있습니다. `results/search_benchmark.json`은 합성 짧은 문서의 계측 결과이며 실제 업무 응답시간이나 전체 프로세스 메모리(RSS)를 의미하지 않습니다.
# 청킹 방식 선택

가상 업무 문서의 근거 검색 비교는 `python scripts/compare_chunking.py`로 실행합니다. 결과는 `results/chunking_comparison.json`에 저장됩니다. 이는 AI 초안 개발 데이터의 원문 문장 검색률이며 실제 업무 성과나 답변 정확도가 아닙니다. 작은 청크 경계 실패를 재현하려면 `--chunk-size 300 --chunk-overlap 40 --output results/chunking_comparison_300.json`을 추가합니다.

기본값은 문서의 페이지·헤딩·문단 경계를 따르는 `structured`입니다. 비교용 `fixed`는 추출 본문을 이어 붙여 일정한 문자 길이로 자르며, 여러 절을 걸치면 출처 위치에 모두 표시합니다.

```powershell
python app.py --chunk-strategy fixed --chunk-size 900 --chunk-overlap 160
```

길이는 토큰 수가 아닌 문자 수입니다. 크기는 1~16000, 겹침은 0 이상 크기 미만이어야 합니다. 옵션을 바꿔 실행한 후 **변경 파일 색인**을 누르면 내용이 같아도 해당 문서를 다시 색인합니다. 재색인 전에는 기존 청크가 유지됩니다. 재색인 후 과거 청크 인용은 새 문단으로 잘못 연결되지 않고 만료됩니다. 실행 옵션은 다음 실행 때도 지정해야 합니다.
